# 开发指南

## 第一次接入

1. 使用 UE 5.8 编译 HOMG2Editor（Development Editor / Win64）。首次加入反射类，关闭使用旧项目 DLL 的编辑器后正常编译，不依赖 Live Coding 热替换反射结构。
2. 将自己 GameMode 的 PlayerControllerClass 设为 AFrameworkPlayerController 或其子类。保留原模板即可，无须修改工程默认地图。本地 Controller 在蓝图 BeginPlay 即可取得 GetUnitPresenter()；远端代理和专用服务器没有 Presenter。在 C++ 子类的 BeginPlay 中先调用 Super，再创建和绑定视图。
3. 由服务端游戏逻辑在游戏线程、Mass 非处理阶段建立实体，并给获授权的玩家发放快照。以下代码放在持有有效 Controller 的服务端上下文。先包含 Framework/Simulation/UnitModel.h、Framework/Network/FrameworkPlayerController.h 和 Framework/Network/UnitFeed.h。

```cpp
auto* Model = GetWorld()->GetSubsystem<UUnitModel>();
if (Controller->HasAuthority() && Model)
{
    const FGuid Unit = Model->CreateUnit(100.f);
    if (Unit.IsValid() && Controller->GetUnitFeed()->Grant(Unit))
    {
        Model->SetHealth(Unit, 20.f); // 示例：客户端只收到 Critical
    }
    // 业务保留 Unit。视野消失调用 Revoke(Unit)；实体消失调用 DestroyUnit(Unit)。
}
```

请求失败返回 false 或无效 GUID；不应为补救失败在客户端新建“权威”实体。服务器改动、复制到达和 UI 创建顺序不固定，绑定视图时总是立即读取当前快照。一个玩家可以获准看到多个单位，但本地只选中其中一个。

## 三种常见改动

**新增属性，例如组织度。** 在 Simulation 新增一个 FMassFragment（或扩充同一生命周期的组件），加入 UUnitModel 的 archetype，创建实体时初始化。只在 Model 中修改精确值。若需展示，给 FUnitSnapshot 增加粗粒度状态，在 ReadUnit 中填充，并扩充 UUnitFeed::Refresh 的变化判断；若仅用于模拟，不修改快照。若改成批量 Processor，需在安全阶段将需要发布的 ID 通知 Feed，不能在 Mass 遍历中调用结构变更。

**新增 UMG。** Widget Blueprint 的父类选 UnitPanel，实现 Render Unit。Snapshot.Id 有效则渲染 Condition，否则清空面板。由本地玩家创建 Widget，Add to Player Screen 后调用 Bind Presenter；移除 Widget 会解除监听，再次显示时重新绑定。按钮、列表或选中逻辑调用 Presenter 的 Select Unit；无权读取的 ID 不会进入选择状态。不要在绑定表达式或 Tick 里轮询 Model。

**新增场景视图。** 在本地可见 Actor 上添加 UnitMarker，调用 Bind Unit(Presenter, Id)。默认使用世界空间文字，可在组件蓝图覆写 Render Unit 来更新材质、图标或其他效果。它持续跟踪这个 ID，玩家切换面板选择不会让它跳到另一个单位。组件 EndPlay 会解除绑定，复用时再次 Bind Unit。面板和场景都只消费快照，不能把生命值写回服务端。

## 启动示例和验证

在编辑器中打开现有地图，控制台输入：

```text
open /Game/TopDown/Lvl_TopDown?game=/Script/HOMG2.FrameworkDemoMode
```

上述命令应在 **Play** 的游戏控制台执行；验证网络时，使用下面的自动化 PIE 测试，或在临时测试地图覆盖 GameMode 为 FrameworkDemoMode，Play 设置选 **Play As Listen Server、2 名玩家**。无需保存对原地图的修改。示例仅用于开发：每个玩家默认选中自己的单位，左上方面板和场景文字初始显示 Healthy；在任一玩家的游戏控制台输入 `DemoDamage`，该玩家的两处显示应同时变为 Critical，另一玩家仍为 Healthy。用 `DemoSelect` 可重选自己的测试单位。离开再进入应重新创建实体、选择和视图。

自动化入口：编辑器 Session Frontend → Automation，运行 `HOMG2.Framework`，运行前先退出手动 PIE。

| 用例 | 验收内容 |
| --- | --- |
| UnitLifecycle | 实体创建、非法输入和数值边界、晚绑定视图、授权撤销及销毁后 ID 失效。 |
| PrivateReplication | 启动双人 PIE，以监听主机和远端客户端验证私有 ID、服务端更新、拥有者 RPC、撤销后的客户端选择。 |

人工画面验收：检查文字是否可读、面板与三维标记是否一致、面板关闭重开后能否显示当前状态。自动化验证状态传播，不等同于人工画面验收。
